# Content Security Policy (CSP) Fix Design Spec

## Overview
`www.displaycellpros.com` encounters Content Security Policy (CSP) violation errors in live production builds due to conflicting, duplicated, or overly restrictive CSP header definitions between `vercel.json` and `next.config.js`. 

This specification outlines the strategy to unify and correctly configure CSP headers in accordance with MDN CSP standards and the application's runtime requirements (Next.js, Builder.io, Shopify, Google Tag Manager, Google Analytics, Google Ads, ElevenLabs, Vercel Live).

## Problem Statement
1. **Conflicting Headers:** `vercel.json` defines a static CSP header that lacks critical domains (GTM, GA, Google Ads, ElevenLabs, etc.), while `next.config.js` defines a much more comprehensive CSP.
2. **Header Duplication / Override:** When deployed on Vercel, static headers in `vercel.json` can override or duplicate headers generated by Next.js `async headers()`, causing browser blocking (CSP errors) for legitimate third-party scripts, analytics, and API connections.
3. **MDN Alignment:** Following [MDN CSP Guidance](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP), policies must accurately whitelist required sources without unnecessary relaxation while avoiding broken integrations.

## Proposed Solution
1. **Remove Static CSP from `vercel.json`:** Eliminate the `Content-Security-Policy` header entry from `vercel.json` so that Next.js (`next.config.js`) serves as the single, authoritative source of truth for all security headers (`Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Strict-Transport-Security`).
2. **Audit & Refine `next.config.js` CSP Directives:**
   - `default-src 'self'`
   - `script-src`: `'self' blob: data: 'unsafe-inline' https://cdn.builder.io https://builder.io https://*.builder.io https://vercel.live https://www.googletagmanager.com https://tagmanager.google.com https://www.googleadservices.com https://www.google.com` (plus `'unsafe-eval'` in development).
   - `style-src`: `'self' 'unsafe-inline' https://www.googletagmanager.com https://tagmanager.google.com https://fonts.googleapis.com`.
   - `img-src`: `'self' data: https://cdn.shopify.com https://cdn.builder.io https://res.cloudinary.com https://via.placeholder.com https://vercel.live https://vercel.com https://*.vercel-insights.com https://www.googletagmanager.com https://ssl.gstatic.com https://www.gstatic.com https://*.google-analytics.com https://*.google.com https://*.g.doubleclick.net https://www.googleadservices.com https://googleads.g.doubleclick.net https://pagead2.googlesyndication.com https://ad.doubleclick.net https://ade.googlesyndication.com https://adservice.google.com https://*.merchant-center-analytics.goog`.
   - `connect-src`: Ensure all Shopify, Builder.io, Google, ElevenLabs, and Vercel endpoints are fully whitelisted.
   - `frame-src`: `'self' https://vercel.live https://www.googletagmanager.com https://*.fls.doubleclick.net`.
3. **Verification Plan:**
   - Run local build (`npm run build`) and test headers (`npm run dev` or production preview).
   - Validate CSP compliance using browser developer tools and security header testing tools.
